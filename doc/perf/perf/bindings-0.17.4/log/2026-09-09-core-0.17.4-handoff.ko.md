# Core 0.17.4 인수 메모 (머신 B → bindings 측정)

- Core main `445e93ca4f`, tag `core/v0.17.4`, Release 자산은 2026-09-09 재빌드본이다.
  `checksums_sha256=f20fc0867e9352e17e48a6333f94f83f8b7227e7d8e9d1855d93691b14ec61bf`,
  `source_sha=445e93ca4f1189df84353c9128f4cff5854e2599`.
- Linux 자산 요구 glibc는 x64·ARM64 모두 **2.34**다(`readelf --dyn-syms`로 확인,
  `__isoc23_*` 참조 0건). provenance에 `linux_x64_glibc_min` / `linux_arm64_glibc_min`이 있다.
  0.17.3 자산(2.38 요구)을 캐시에 두고 있으면 지우고 다시 받는다.
- Core 쪽 측정값(참고, 머신 B WSL 16코어/11.9 GiB, `bindings/c/bench/with_stream`,
  CCU 1000, idle 3-run 중앙값):

  | 셀 | 0.17.3 | 0.17.4 |
  |---|---:|---:|
  | STREAM tcp 64 B kops | 270.6 | 270.0 |
  | STREAM tcp 1 KiB kops | 250.1 | 256.1 |
  | STREAM tcp 64 KiB kops | 32.3 | 40.3 |
  | STREAM tcp 64 KiB p99 ms | 22.8 | 17.4 |
  | STREAM 64 B CCU 4000 | 실패 | 209 kops |
  | ws round-trip Q64/Q1 게이트 | 0.53 FAIL | 0.85~1.30 PASS |

  이 값은 Core 벤치(with_stream) 기준이며 bindings perf 러너의 판정 기준이 아니다.
  bindings 판정은 언제나 같은 시점에 짝지어 잰 `bindings/c/perf` 결과와 비교한다.
- Core 이슈는 `doc/plan/c016-worklog/decisions.ko.md`에 `D-BP` 항목으로 적는다.
  0.17.5 후보로 이미 등록된 것: 메시지당 고정 비용 축소(SC-1~4), decoder read target 상한
  정책(D-S1), WS 3-buffer pending 취소 테스트, Auto-HWM timer wake 관측 테스트,
  perf 러너 `--io-threads` alias 문서 불일치.
