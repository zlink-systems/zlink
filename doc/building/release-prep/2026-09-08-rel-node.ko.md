# rel-node 공개 배포 준비 기록

이 문서는 감독자가 npm 공개 배포용 변경과 최초 수동 배포 순서를 검토할 때 필요한
결과를 기록한다. 대상은 `@zlink-systems/zlink` 0.17.3과
`.github/workflows/bindings-release.yml`의 `release-node` job이다.

## 변경 파일

- `bindings/node/package.json`
- `bindings/node/provenance/core-package-provenance.json`
- `.github/workflows/bindings-release.yml`의 `release-node` job
- `doc/building/release-prep/2026-09-08-rel-node.ko.md`

## package metadata와 배포 파일

기존 package 이름은 이미 `@zlink-systems/zlink`였다. 다음 metadata를 확인하거나
추가했다.

- `license`: `MPL-2.0`
- `repository`: `https://github.com/zlink-systems/zlink.git`, directory
  `bindings/node`
- `homepage`: `https://zlink.systems/`
- `bugs`: `https://github.com/zlink-systems/zlink/issues`
- `engines.node`: `>=22`
- `publishConfig.access`: `public`
- `publishConfig.provenance`: `true`

`files`는 실행 결과물과 native 설치에 필요한 파일로 제한했다. `dist`, 플랫폼별
`zlink.node`, 플랫폼별 Core runtime, Core provenance, `README.md`, `LICENSE`,
`THIRD_PARTY_NOTICES.md`가 배포 대상이다. 플랫폼 prebuild가 없는 source checkout의
fallback을 유지하기 위해 `binding.gyp`, `native/src`, `scripts/install.js`,
`scripts/resolve_core.js`도 포함한다. test, perf, sample, Typedoc 설정과 배포 전용
검증 script는 allowlist에 넣지 않았다. npm 자체 규칙 때문에 `README.typedoc.md`는
README 계열 파일로 자동 포함된다.

Linux runtime은 정확한 버전의 `libzlink.so.0.17.3`만 tarball에 넣는다.
`libzlink.so.0` symlink까지 넓은 glob으로 포함하면 npm pack이 symlink를 실제 파일로
풀어 Core runtime을 중복 저장했다. 실행 시 `native_load_paths`가 package provenance의
version을 읽고 `libzlink.so.0` symlink를 만든다.

## native addon 배포 방식

`scripts/install.js`는 현재 platform과 architecture에 맞는
`prebuilds/<platform>-<arch>/zlink.node`가 있으면 설치 중 native compile을 생략한다.
prebuild가 없으면 `node-gyp rebuild`를 실행한다. source-build fallback에는 compiler와
해당 platform의 Core package prefix가 필요하다.

현재 `release-node` job이 만드는 prebuild는 Linux x64뿐이다. Linux x64 사용자는
tarball에 포함된 `zlink.node`와 `libzlink.so.0.17.3`을 사용한다. 다른 platform은
해당 prebuild가 package에 추가되기 전까지 source-build fallback 조건을 충족해야 한다.

package에 포함되는 Core provenance는 검증된
`~/.cache/zlink/core/0.17.3/linux-x64`의 파일과 byte 단위로 일치시켰다. workflow도
`scripts/local-package/core/fetch-release.sh`로 검증된 Core 0.17.3 prefix를 준비한 뒤,
그 prefix 하나에서 header, runtime과 provenance를 가져온다.

## GitHub Actions npm 배포

`release-node` job은 다음 조건으로 npm Trusted Publishing을 사용한다.

- job permissions: `contents: write`, `id-token: write`
- GitHub-hosted Ubuntu runner와 Node 22
- `actions/setup-node` registry: `https://registry.npmjs.org`
- `npm install -g npm@latest`
- `npm publish --provenance --access public`
- `NPM_TOKEN`과 npm auth 파일 생성 없음

npm Trusted Publishing은 npm CLI 11.5.1 이상과 Node 22.14.0 이상이 필요하다.
GitHub Actions 설정 필드는 npm의
[Trusted publishing 문서](https://docs.npmjs.com/trusted-publishers/)와
[provenance 문서](https://docs.npmjs.com/generating-provenance-statements/)를 기준으로
확인했다.

## 최초 수동 배포 절차

최초 publish는 package가 아직 npm에 없어서 Trusted Publisher를 먼저 등록할 수 없는
경우에만 사용한다. Core release prefix가 이미 준비된 Linux x64 clean checkout에서
다음 순서로 실행한다.

```bash
cd /home/hep7/project/zlink/bindings/node

export ZLINK_CORE_INSTALL_PREFIX="$HOME/.cache/zlink/core/0.17.3/linux-x64"
export ZLINK_CORE_VERSION=0.17.3

npm install -g npm@latest
npm --version
npm ci
npm run build
npm run rebuild-native

install -d prebuilds/linux-x64 provenance
install -m 0755 build/Release/zlink.node prebuilds/linux-x64/zlink.node
install -m 0755 \
  "$ZLINK_CORE_INSTALL_PREFIX/lib/libzlink.so.0.17.3" \
  prebuilds/linux-x64/libzlink.so.0.17.3
ln -sfn libzlink.so.0.17.3 prebuilds/linux-x64/libzlink.so.0
ln -sfn libzlink.so.0 prebuilds/linux-x64/libzlink.so
cp "$ZLINK_CORE_INSTALL_PREFIX/share/zlink/core-package-provenance.json" \
  provenance/core-package-provenance.json

npm run verify:prebuilds
npm pack --dry-run
npm pack

npm login --scope=@zlink-systems --registry=https://registry.npmjs.org
npm whoami
NPM_CONFIG_PROVENANCE=false npm publish --access public
```

`npm --version` 출력은 11.5.1 이상이어야 한다. `npm login`은 `zlink-systems` 계정으로
완료하고 2FA 요청을 승인한다. package의 `publishConfig.provenance`가 `true`이지만
provenance 생성은 지원되는 CI 환경에서만 가능하므로, 최초 로컬 publish 한 번만
`NPM_CONFIG_PROVENANCE=false`로 덮어쓴다. 이후 publish에서는 이 override를 사용하지
않는다.

최초 publish가 성공하면 npmjs.com의 `@zlink-systems/zlink` package settings에서
Trusted Publisher를 다음 순서로 연결한다.

1. Provider에서 GitHub Actions를 선택한다.
2. Organization or user에 `zlink-systems`를 입력한다.
3. Repository에 `zlink`를 입력한다.
4. Workflow filename에 경로 없이 `bindings-release.yml`을 입력한다.
5. Environment name은 비워 둔다.
6. Allowed actions에서 direct `npm publish`를 허용한다.
7. 저장한 뒤 다음 정식 release에서 OIDC publish와 provenance 표시를 확인한다.

Node 배포용 GitHub secret은 만들지 않는다. `NPM_TOKEN`도 생성하거나 등록하지 않는다.

## 미해결 사항

- npm login, 최초 publish와 Trusted Publisher 등록은 외부 상태를 바꾸므로 실행하지 않았다.
- workflow는 실행하지 않았다. 최초 수동 publish와 Trusted Publisher 등록 뒤 정식 release에서
  OIDC 인증과 provenance 생성을 확인해야 한다.
- 자동 생성 prebuild는 현재 Linux x64로 한정된다. macOS와 Windows 사용자가 설치 시 compile을
  피하려면 각 platform prebuild를 별도 release job에서 만들어 같은 package에 합치는 작업이
  필요하다.
- npm이 `README.typedoc.md`를 README 계열 파일로 자동 포함하므로 `files` allowlist만으로는
  제외되지 않는다.
