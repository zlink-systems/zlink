# Bindings spec redline 변경표

D-109에서 수락한 F-R3-3…10과 F-R3-1의 문장 하나를 반영한 검토용 수정본이다.
**적용한 모든 항목의 행동 변경: 없음.** 원본을 교체하지 않았고 실행 코드·공개 API 구현을 변경하지 않았다.
D-109의 F-R3-2 문서 언급보다 이번 job의 명시적 제외 지시를 우선했다.

수정본은 지정된 11개 문서의 ko/en 전체 사본 22개다. 표의 old lines는 수정 전 작업 트리 원본의 행 번호다.
R3 보고서의 Core socket 인용은 과거 commit 기준이므로 현행 소유 문서에서 다시 확인했다.

## 적용하지 않은 주장과 범위

- **F-R3-2와 F-R3-11…17:** 구현은 머신 B 소유다. F-R3-2의 “최종 저장소가 한 번만 채택” 문장을 추가하지 않았고,
  기존 수신 저장소 계약을 유지했다. F-R3-11…17을 새 규칙·완화된 assertion·언어별 예외로 만들지 않았다.
- **F-R3-5:** “모든 바인딩이 native FINAL 전에 provisional registry에 등록한다”는 구현 주장은 성립하지 않는다.
  Java·Go의 제출 후 등록과 C++의 조기 완료 보관을 확인했으므로 그 알고리즘을 문서상 강제하지 않는다.
- **F-R3-6의 Java codec 디렉터리:** `bindings/doc/spec/java/README.ko.md:204–205`와 en `:216–217`을 유지했다.
  `bindings/java/settings.gradle:2–3`과 `bindings/java/codec/zlink-ext-netty/build.gradle:8, 22–24`는 실제 Netty
  buffer adapter를 가리킨다. 디렉터리 이름만으로 폐기할 serializer codec이라는 주장은 성립하지 않는다.
- **F-R3-9의 Node en:** 원문 `:779–780`은 per-handle request progress 설명이며 Core callback/TSFN 문장이 아니다.
  삭제할 TSFN 문구가 있다고 기록하지 않고, ko와 같은 공통 owner 참조로 정렬했다.
- SPOT·Actor의 service callback API는 이 job에서 제거하거나 새 raw Core API로 바꾸지 않았다.

## 정적 확인

- 지정 문서 22개 전체 수정본을 작성했다. 원본 22개 SHA-256은 작성 전후 동일하다.
- 추가 링크는 원래 배치 경로 기준으로 파일과 anchor를 확인했다. Ko/en 제목 계층과 수정한 절의 순서·표·코드 선언을 대조했다.
- 새 trailing whitespace와 닫히지 않은 code fence는 없다.
- 빌드·unit test·E2E·benchmark·gate·설치·commit·push·git 상태 변경 명령은 실행하지 않았다.
- 문서 소유 위치는 F-R3-3의 수신 회계/수명 10 → 1, F-R3-4의 receive-flow 투영 8 → 1,
  F-R3-5의 완료 합류 9 → 1로 통합했다. 이는 규정 위치의 수이며 B가 소유한 runtime 검사·상태의 제거 완료를 뜻하지 않는다.
