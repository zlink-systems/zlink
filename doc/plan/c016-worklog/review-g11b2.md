## 권고

**특정 수정 후 진행.** 최소 차단 수정은 (1) odd sequence에서 미초기화 값을 읽지 않는 reader loop로 교체, (2) monitor의 local inbound msgs/bytes도 같은 message 경계로 coherent publication, (3) CAS/store 범위를 실제 코드대로 결과 보고서에 정정하는 것이다. 그 뒤 synchronization §6이 요구하는 TSan/lost-wake와 Monitoring §6.3 contract test, 그리고 pristine 대비 cycle/throughput을 게이트에서 다시 확인한다.

## 총평

Session writer의 ledger data race를 full-width atomic과 single-writer sequence로 옮긴 방향은 synchronization model §3.2에 맞는다.
Writer publication 순서, 64-bit atomicity, session/inproc writer ownership과 새 lock 순서는 정적으로 타당했다.
그러나 odd sequence reader는 첫 재시도에서 미초기화 값을 읽는 명백한 undefined behavior가 있다.
또한 peer written pair만 묶었고 local read pair는 묶지 않아 Monitoring §6.3의 pipe 합계 군 일관성이 완성되지 않았다.
`_out_active`의 경쟁 async recovery CAS는 wake 단독 승자를 유지하지만, “credit recovery 전부 CAS”라는 보고서 문장은 코드보다 넓다.
Ir −0.45%는 instruction gate 근거일 뿐 locked RMW의 cycle 비용까지 배제하지 못한다.
따라서 현 상태는 게이트 직행이 아니라 위 세 수정 후 진행이 적절하다.
