# 0.17.4 동기화·I/O 구현 사실 채록

이 문서는 `main`의 0.17.4 착지 코드에서 관찰한 동작을 채록한 것이다. 아래 문장은 새 계약이나 권고가 아니라 현재 구현의 제어 흐름, 원자 연산, 잠금 범위와 소유자를 요약한다. 소스·스펙·테스트는 변경하지 않았고 빌드·실행도 하지 않았다.

## 1. socket turn

| 규칙 문장 | 근거 파일:행 |
|---|---|
| `public_api_state`의 bit 63은 close, bit 62는 socket turn(sync), bit 61은 incremental multipart lease이다. bit 32..60은 complete-record admission 수(단위 `1 << 32`, 29비트), bit 0..31은 실행 중 public API 수이다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:18-28`, `core/src/runtime/sockets/common/socket_runtime.hpp:709-724` |
| 일반 public API admission은 low word에 `fetch_add(1, acq_rel)`하고 close bit가 이미 보이면 `fetch_sub(1, acq_rel)`로 되돌린 뒤 `ESHUTDOWN`을 반환한다. 반납도 `fetch_sub(1, acq_rel)`이다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:82-116` |
| admission과 turn을 동시에 얻는 무경합 경로는 상태어 `0`을 `1 | sync_bit`로 바꾸는 strong CAS를 쓴다. 성공 order는 `acq_rel`, 실패 order는 `acquire`이며, 실패하면 admission 후 별도 turn CAS로 간다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:95-109` |
| send admission은 acquire load 뒤 weak CAS(`acq_rel`/`acquire`)로 low-word admission과 multipart bit 또는 complete-record count를 함께 올리고, 가능한 경우 sync bit도 같은 CAS에서 세운다. multipart와 complete-record admission은 상호 배타적이다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:118-178` |
| send 반납은 admission, multipart/complete 표지, 보유 중인 sync bit를 한 번의 `fetch_sub(acq_rel)`로 내린다. multipart call을 대기 중 suspend할 때에는 multipart bit만 남기고 low-word admission과 sync bit를 내린다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:181-220`, `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:266-281` |
| turn 획득은 상태어 acquire load와 weak CAS를 사용한다. CAS 성공·실패 모두 `acquire`이고, 반납은 sync bit에 대한 `fetch_and(..., release)`이다. admission까지 함께 반납하는 경로는 `fetch_sub(sync_bit | 1, acq_rel)`이다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:415-452` |
| 경합 backoff는 처음 64회까지 spin, 1024회 미만까지 `yield`, 그 뒤에는 100µs sleep이다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:32-50` |
| 현재 thread가 같은 coordinator의 turn을 이미 소유하면 receive/command 내부 재진입은 새 turn을 얻지 않는다. 소유 여부는 thread-local coordinator 연결 목록으로 판정하고, 내부 scope는 자신이 실제 획득한 경우에만 반납한다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:54-70`, `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:383-413`, `core/src/runtime/sockets/common/socket_runtime.hpp:354-375` |
| `process_commands()`는 command batch 시작 전에 현재 thread 소유 여부를 보고 turn을 획득하며, mailbox dequeue, `process_command`, deferred pipe termination, readiness/submit-progress publication까지 같은 turn 안에서 수행한다. 이미 turn을 가진 public/command 호출은 그 자리에서 drain한다. | `core/src/runtime/sockets/common/socket_base_lifecycle.cpp:375-426`, `core/src/runtime/sockets/common/socket_base_lifecycle.cpp:487-561` |
| blocking command wait는 command scope가 끝나 turn이 반납된 뒤 `wait_for_command_signal()`에 들어간다. wake 뒤에는 loop 상단의 다음 command scope에서 turn을 다시 얻은 뒤 command를 claim한다. | `core/src/runtime/sockets/common/socket_base_lifecycle.cpp:561-581` |
| blocking receive의 async-owner 경로는 turn 아래 waiter를 `seq_cst`로 등록하고 scope 종료로 turn을 놓은 뒤 progress mutex/CV에서 기다린다. wake 뒤 public recv loop가 `receive_once_guarded()`를 다시 호출해 turn을 재획득한다. | `core/src/runtime/sockets/common/socket_base_lifecycle.cpp:1594-1624`, `core/src/runtime/sockets/common/socket_base_msg.cpp:699-718` |
| blocking send는 async command owner가 진행할 수 있는 경우 retry 전에 sync bit를 내린다. `process_commands()`가 끝난 다음 sync bit를 재획득하고 `xsend*()`를 재시도하며, 다시 막히면 다음 wait 전에 다시 내린다. 오류 중 rollback이 필요하면 rollback helper가 먼저 turn을 재획득한다. | `core/src/runtime/sockets/common/socket_base_msg.cpp:535-608`, `core/src/runtime/sockets/common/socket_base_msg.cpp:630-642`, `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:532-564` |
| close admission은 sync bit를 기다리거나 획득하지 않는다. low-word in-flight가 0일 때 close bit를 weak CAS(`acq_rel`/`acquire`)로 세우며, 남아 있는 multipart bit와 async command owner의 raw sync bit는 실행 중 public API로 세지 않는다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:301-340` |
| poller 등록은 lifetime pin을 잡는 순간에만 public admission을 얻었다가 즉시 반납한다. 등록 수명 전체를 상태어에 남기지 않으므로 등록된 socket의 close를 막지 않는다. | `core/src/runtime/sockets/common/socket_lifecycle_runtime.cpp:284-293` |
| close 경로는 `begin_close_or_fail_busy()`로 close gate를 먼저 게시하고 progress/mailbox edge를 낸 뒤 async handoff와 reap을 마친다. 이 경로 자체는 socket turn scope를 만들지 않는다. | `core/src/runtime/sockets/common/socket_base_control.cpp:13-43`, `core/src/runtime/sockets/common/socket_base_api.cpp:164-190` |

## 3. pipe 두 끝

| 규칙 문장 | 근거 파일:행 |
|---|---|
| ypipe는 한 시점에 reader thread 하나, writer thread 하나인 SPSC 구조이다. `yqueue`도 push/back 한 thread와 pop/front 다른 한 thread만 허용한다. | `core/src/runtime/core/ypipe.hpp:12-17`, `core/src/runtime/core/yqueue.hpp:15-22` |
| pipe outbound cluster(`_out_pipe`, `_state`, `_out_active`, peer credit)의 C2 writer는 endpoint owner 하나이다. socket endpoint는 socket lifecycle turn, session endpoint는 I/O thread가 그 owner이다. inbound `_in_active`는 receive owner와 command owner가 공유하므로 atomic이다. | `core/src/runtime/core/pipe.hpp:735-753` |

| reconnect/hiccup은 `_out_sync` 아래 old queue와 outbound generation/counters를 교체한다. terminate와 delimiter도 같은 lock 아래 lifecycle state를 바꾼다. | `core/src/runtime/core/pipe_transport.cpp:148-205`, `core/src/runtime/core/pipe_transport.cpp:375-410`, `core/src/runtime/core/pipe_transport.cpp:492-547` |

## 4. mailbox와 깨어남

| 규칙 문장 | 근거 파일:행 |
|---|---|
| mailbox command queue도 SPSC ypipe이므로 arbitrary producer들은 `_sync` 하나로 writer endpoint를 직렬화한다. receive endpoint는 socket runtime handoff 또는 전용 I/O/reaper/termination consumer 하나가 소유한다. | `core/src/runtime/core/mailbox.hpp:118-131` |
| `send()`의 `_sync` 범위에는 command write+flush, 관찰자 epoch/CV 갱신, pending hint, 등록 poller signal, 필요 시 primary signal, Asio scheduling 결정이 모두 포함된다. | `core/src/runtime/core/mailbox.cpp:65-96` |
| command wake 원인은 empty/sleeping reader에서 pending work로 바뀌는 ypipe transition이다. `_cpipe.flush()`가 false인 경우에만 hint와 signal/post를 내므로 이미 active인 receiver에 이어 붙은 command는 별도 wake를 만들지 않는다. | `core/src/runtime/core/mailbox.cpp:68-96`, `core/src/runtime/core/ypipe.hpp:73-98` |
| Asio executor가 설치돼 있으면 `_scheduled.exchange(true, acquire)`가 한 callback만 post하도록 coalesce한다. callback drain 후 `reschedule_if_needed()`가 `_sync` 아래 scheduled를 내리고 queue를 재확인해, 데이터가 남으면 예약을 유지한다. | `core/src/runtime/core/mailbox.cpp:335-391` |
| Asio executor가 있어도 public FD/poller 사용이 게시돼 있으면 primary signaler에도 신호한다. public descriptor 사용이 없고 registered signaler도 없으면 Asio post만으로 owner를 깨우며 불필요한 primary eventfd write를 생략한다. | `core/src/runtime/core/mailbox.cpp:59-63`, `core/src/runtime/core/mailbox.cpp:78-95` |
| 첫 POSIX poller registration은 primary descriptor를 소유하고, 이후 registration은 mailbox에 secondary signaler를 등록한다. poller의 shared secondary signaler는 `signaler_t(true)`로 생성된다. | `core/src/runtime/core/mailbox.cpp:437-488`, `core/src/runtime/core/socket_poller.cpp:512-539` |
| coalescing signaler는 `_signaled.exchange(true, acq_rel)`가 이미 true이면 syscall을 생략한다. consume 시 `_signaled=false`를 release store한다. | `core/src/runtime/core/signaler.cpp:191-210`, `core/src/runtime/core/signaler.cpp:407-425` |
| mailbox receiver는 command pipe를 authoritative source로 먼저 보고 `_active`를 consumer-local state로 갱신한다. shared signaler 목록을 볼 때만 잠깐 `_sync`를 잡고, 실제 wait와 cpipe read에는 producer lock을 유지하지 않는다. | `core/src/runtime/core/mailbox.cpp:124-199` |
| blocking command wait의 enqueue-versus-registration race는 `_sync` 아래 command epoch, pending hint, waiter count와 CV로 닫는다. 일반 active send는 observer/waiter가 없으면 epoch/CV 비용을 내지 않는다. | `core/src/runtime/core/mailbox.cpp:65-77`, `core/src/runtime/core/mailbox.cpp:238-305` |

## 5. Auto-HWM

| 규칙 문장 | 근거 파일:행 |
|---|---|
| context option/input은 recursive `_opt_sync`, generation/deadline/applied-plan/task state는 recursive `_auto_hwm_state_sync`, 전체 replan 및 incremental extension 직렬화는 recursive `_auto_hwm_recalc_sync`, socket registry lifetime snapshot은 non-recursive `_slot_sync`가 각각 소유한다. | `core/src/runtime/core/ctx.hpp:191-206`, `core/src/runtime/core/ctx.hpp:220-233` |
| 일반 replan schedule은 `_opt_sync`로 debounce 입력을 읽은 뒤 별도 `_auto_hwm_state_sync` 구간에서 generation과 deadline을 갱신한다. debounce가 0 이하면 즉시 full replan을 호출하고, 양수이면 task를 시작/재예약한다. | `core/src/runtime/core/ctx_auto_hwm_recalc.cpp:86-117`, `core/src/runtime/core/ctx_auto_hwm_state.cpp:239-250` |
| convergence debounce는 generation을 올리지 않는다. `_recalc_deadline_ms==0`인 첫 caller만 deadline을 arm하고 timer를 깨우며, 같은 burst의 후속 attach는 이미 잡힌 deadline에 합류한다. | `core/src/runtime/core/ctx_auto_hwm_recalc.cpp:119-159`, `core/src/runtime/core/ctx_auto_hwm_state.cpp:252-263` |

## 확인 불가 또는 정적 채록 한계

- close 시 RID storage를 별도 clear하는 문장은 찾지 못했다. 공개 헤더는 close에서 view가 무효화된다고 명시하고, 실제 close는 socket lifetime 종료로 storage 자체를 회수하지만, close 경로의 명시적 `clear_last_recv_source_rid()` 호출은 확인되지 않았다 (`core/include/zlink/socket/api.h:281-284`, `core/src/runtime/sockets/common/socket_base_api.cpp:164-190`).
- command의 virtual destination 전체를 열거해 `process_command()` 아래에서 생길 수 있는 모든 socket별 mutex 조합까지 증명하지는 못했다. 이 문서의 잠금 순서는 요청된 turn/receive/pipe/mailbox/Auto-HWM/Asio/WS 경로에서 실제로 중첩되는 조합이다 (`core/src/runtime/sockets/common/socket_base_lifecycle.cpp:502-524`).
- static source만 채록했으므로 경합 빈도, 평균 CAS 재시도 수, syscall당 실제 batch 크기와 같은 동적 수치는 확인 불가이다.
