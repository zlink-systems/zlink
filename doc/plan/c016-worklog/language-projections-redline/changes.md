# R8 language projections redline

D-114의 문서 전용 finding **F-R8-1·2·4·5·6·7·20**을 반영한 검토용 수정본이다. 원래 `framework/doc/**`, `core/**`, `bindings/**`, `doc/site/**`에는 쓰지 않았다. `main`의 현재 원문을 읽었으며 기존 working-tree 변경을 보존했다. D-101·D-104–108의 변경은 수정 범위 밖에서 유지했다.

이 디렉터리에는 ko/en **35쌍(70개)**의 전체 문서 사본이 있다. **68개는 수정본**, Kotlin interface README 2개는 F-R8-7의 대응 의무를 확인한 **원문 그대로의 대조용 사본**이다. 다른 common 문서와 public source는 읽기 전용 근거이며 사본을 추가하지 않았다.

## 검증에서 제한하거나 적용하지 않은 주장

- **F-R8-5:** “모든 언어의 HTTP 산출물이 Framework runtime binary를 전혀 포함하지 않는다”는 일반화는 적용하지 않았다. 실제 C++ target은 Framework target을, Java는 core project를, Node는 Framework package를 참조한다. .NET만 확인된 `Zlink.Framework.Contracts` 분할을 그 언어의 투영으로 명시했다. 공통 §1.3은 HTTP가 Framework 계약을 소비하는 방향과 host 시작을 요구하지 않는 사용 경계를 소유하며, 언어별 산출물의 구성 자체를 바꾸지 않는다.
- **F-R8-6:** Node foundation의 설정 선언은 이미 올바르다. NestJS 사본의 누락 선언과 잘못 연결한 HWM 설명만 정정했다.
- **F-R8-7:** Java의 생성 응답 선언과 Kotlin README의 source/JVM 대응 의무는 이미 올바르므로 변경하지 않았다. Kotlin Spot 문서의 generated 반환형만 실제 Kotlin override·suspend hook 및 Java superinterface와 맞췄다. JVM bytecode를 새로 생성하거나 `javap`를 실행하지 않았다.
- **F-R8-20:** public marker·stable type·완료 타입을 대조했다. 다섯 runtime의 durable recovery 전이를 실행 검증한 결과가 아니다. 공통 §4 밖의 marker 검증·실패 recovery 문장을 무조건 삭제하지 않은 이유는 위 SUPERVISOR-DECIDE에 기록했다.
- **F-R8-3:** D-114에서 감독자가 처리한 gate 수정은 대상 밖이다. Gate를 실행하거나 다시 수정하지 않았다.
