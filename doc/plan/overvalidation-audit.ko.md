### 총수와 우선순위

- **과잉 14개:** A 9, B 0, C 5.
- **[의심] 2개.**
- command-38의 **OwnerLeaseGeneration equality 비교는 현재 코드에 없습니다**. 남은 문제는 Store authority lookup의 추가 veto(C)입니다.
- P0:
  - [spot_runtime.cpp:10826](../../framework/languages/cpp/framework/src/runtime/spots/spot_runtime.cpp#L10826)의 최종 Actor dispatch generation veto.
  - 일반 Actor/Spot source·local admission의 A 패턴.
  - command-36 source/Session-owner lease 조건.
- P1:
  - command-38 Store projection veto.
  - command-24 target-route projection veto.
  - Deferred Join completion의 current-generation 재검사.
- P2: 두 `[의심]` projection/high-water 분기의 실제 후속 전달 영향 확인.

규범 문서 자체에도 두 충돌이 있습니다. `08-routing §2.6`은 ActorRef를 application target에서 제외하지만 [04-actor-model §8.1](../../framework/doc/framework/common/spec/server/03-spot-actor/04-actor-model.ko.md#81-실패)은 ActorRef direct call의 generation mismatch를 `InvalidOperation`으로 적고 있습니다. 또 binding §5는 command-38 승인에서 lease를 명시적으로 제외하지만 [routing §3.1](../../framework/doc/framework/common/spec/server/03-spot-actor/08-routing.ko.md#31-bind할-때-route를-저장한다)은 current owner lease를 열거합니다. 이번 판정은 요청에 명시된 룰북과 더 구체적인 binding §5를 우선했습니다.

저장소 파일 변경, git 조작, 빌드·테스트는 하지 않았습니다. 과거 메모리는 C++ binding/identity 후보를 좁히는 용도로만 사용했고, 모든 판정은 현재 checkout에서 다시 확인했습니다.
