## 요약

- 불일치 5건: R14, R22, R47, R48, R49
  - R14: 서로 다른 stream node에 같은 session type을 등록하는 것을 막는 검사가 없음(스펙 해석에 따라 갈릴 수 있음)
  - R22: 기본 `SpotWide` User Spot 실행 모드에서 서로 다른 Actor가 Spot 공유 큐로 직렬화됨(스펙은 "Spot global queue로 직렬화하지 않는다"고 규정)
  - R47: command 44 commit 시 seal 해제가 held message 제출보다 먼저 일어나고(스펙은 적용→제출→해제 순서), tenure 불일치 시 held frame이 target route로 제출되지 않고 폐기됨

  - R49: relay-ready accept 전 abort 시 held message가 source route로 재제출되지 않고 폐기됨(스펙은 source route로 재제출을 요구)
- 스펙 미정 2건: R52, R56
  - R52: infrastructure task(detached async task) 방식은 코드가 선택했으나 모든 completion 경로를 전수 확인하지 못함
  - R56: 단일 실행 engine은 확인했으나, 자리별(Spot/session/Actor) typed lane policy 대신 flat 2값 enum(`Application`/`Lifecycle`)으로 더 단순하게 구현
