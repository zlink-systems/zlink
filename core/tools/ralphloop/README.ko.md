# Ralphloop 사용 규칙

`core/tools/ralphloop/` 는 개별 스펙 문서를 반복 실행 가능한 랄프 세트로
묶을 때 재사용하는 공용 supervisor/gate 스크립트 폴더다.

핵심 목표는 고정 POSD 루프를 복제하는 것이 아니라,
"이미 작성된 스펙 문서를 끝까지 완료할 수 있는 랄프 루프"를
각 스펙마다 새로 구성하는 것이다.

## 기본 의도

사용자가 스펙 문서 경로와 대상 디렉터리를 주면서
`이걸 이용해서 랄프 스크립트와 가이드 문서를 작성해줘` 라고 요청하면,
기본 산출물은 아래처럼 고정한다.

사용자가 단순히 `랄프루프 만들어줘` 라고만 말해도 기본 해석은 같다.
즉 별도 경로를 다시 쓰지 않아도 `core/tools/ralphloop/` 기반으로
스펙 전용 wrapper와 실행가이드를 만든다.

- 대상 디렉터리의 wrapper 스크립트 1개
- 대상 디렉터리의 실행가이드 문서 1개
- 실행 중 생성되는 `logs/` 디렉터리

기본값으로 아래 문서는 만들지 않는다.

- 별도 main 문서
- 별도 master plan 문서
- gap review 문서
- residual spec 문서
- 보조 계획서 전반

필요한 계획, 종료 조건, 검증 규칙은 실행가이드 한 파일에 흡수한다.
다만 실행 중 상태 기록은 기본적으로 각 session `logs/` 디렉터리 아래 파일에 남긴다.
문서를 둘 이상으로 나누는 것은 사용자가 명시적으로 요청할 때만 허용한다.

## 실행가이드 작성 규칙

새 실행가이드는 아래를 한 파일 안에 모두 포함해야 한다.

- 목적과 대상 범위
- 적용 원칙과 금지 규칙
- iteration 순서
- 검증 절차
- 종료 조건
- 로그/commit/push 운영 규칙
- session 로그 디렉터리에 남길 상태 파일 규칙

즉 "계획 문서"와 "실행 문서"를 분리하지 않는다.
실행가이드가 곧 유일한 authority 문서다.
실행 상태, 체크리스트, handoff, 메모는 session 로그 디렉터리 산출물로 분리한다.

## 스펙 적응 원칙

새 랄프 세트를 만들 때는 공용 스크립트를 그대로 복사하는 것이 아니라,
주어진 스펙 문서의 완료 조건에 맞게 wrapper와 실행가이드를 조정해야 한다.

반드시 스펙에 맞게 달라져야 하는 항목:

- 대상 범위
- 빌드/테스트/검증 명령
- session 로그 디렉터리에 남길 상태 파일 구조
- 종료 조건
- 실패 시 재현 및 복구 절차
- commit/push 규칙
- 장시간 gate 필요 여부와 종류

즉 사용자가 스펙 문서 경로와 대상 디렉터리를 주면,
결과물은 "그 스펙을 끝까지 소화하는 실행가이드 1개"와
"그 실행가이드를 반복 실행하는 wrapper 1개"여야 한다.

허용되지 않는 기본 동작:

- 기존 POSD 가이드 문구를 거의 그대로 복사하는 것
- 스펙과 무관한 gate나 테스트 명령을 그대로 재사용하는 것
- 종료 조건이 스펙 완료가 아니라 단순 테스트 통과로 축소되는 것
- 구현/문서/검증 기준이 스펙 바깥의 옛 문서들에 의존하도록 만드는 것

권장 기본 흐름:

1. 사용자가 준 스펙 문서를 읽는다.
2. 그 스펙의 완료 판정과 검증 surface를 추출한다.
3. 실행가이드 한 파일에 계획, 작업 순서, 검증, 종료 규칙을 통합한다.
4. wrapper는 그 실행가이드와 스펙 전용 gate/로그 규칙에 맞춰 만든다.
5. session 로그 디렉터리에 기본 `run_state`, `checklist`, `notes`, `handoff` 파일이 생성되고,
   새 실행은 직전 session의 미완료 사항을 먼저 확인하도록 만든다.
6. 생성 후 실제로 짧게 실행해 동작을 검증한다.

## session 로그 기본 규칙

새 Ralph loop는 기본적으로 각 실행 session마다 아래 파일을 로그 디렉터리에 만든다.

- `00_run_state.md`
- `00_checklist.md`
- `00_notes.md`
- `00_handoff.md`

기본 동작:

- 실행 상태 체크와 진행 메모는 실행가이드 본문이 아니라 위 session 파일에 기록한다.
- 새 session이 시작되면 직전 session dir를 확인하고 미완료 사항을 먼저 이어받는다.
- 실행가이드는 정책, 범위, 완료 기준이 바뀔 때만 수정한다.
- 반복적 진행 로그, 임시 판단, 이번 실행의 체크 표시는 session 로그 파일에 남긴다.

## wrapper 작성 규칙

새 wrapper는 `core/tools/ralphloop/run_codex_execution_guide_loop.sh` 를 호출한다.

기본값:

- `--guide` 와 `--master-plan` 은 같은 실행가이드 경로를 가리킨다.
- 기존 supervisor 중복 확인은 기본적으로 끈다.
- gate lock 강제도 기본적으로 끈다.

사용자가 요청할 때만 아래 옵션을 켠다.

- wrapper 쪽 `--check-existing-supervisor`
- gate 쪽 `--enforce-lock`

## supervisor 해석 규칙

`run_codex_execution_guide_loop.sh` 는 단일 실행가이드 체계를 기본값으로 본다.

- 현재 실행의 유일한 기준 문서는 실행가이드다.
- legacy 보조 문서 경로가 들어와도 새 문서를 추가 생성하지 않는다.
- 필요한 내용이 남아 있으면 실행가이드로 먼저 합친 뒤 계속 진행한다.
- 명시 요청이 없으면 guide/main/master 문서 세트를 유지하지 않는다.
