# #4350 Ladder L0 — Node

## 판정

L0 코드는 실험 브랜치 `exp/4350-node-ladder`에만 커밋했다. L0와 binding의 6개 셀을 각 3회 측정했으며 모든 실행에서 오류는 0, `submitted = completed = target_stats.received`였다. **L0는 4/6 셀에서 0.95 기준을 통과했고, request-serial 1K·4K는 각각 0.9373·0.9384로 미달했다.** 미달 원인은 아래에 남은 L0 계측 및 수신 대기 비용으로 기록했다.

PM 2026-11-12 08:30 UTC 결정에 따라 main은 재측정하지 않았다. main 수치는 커밋 `d3fd955131`의 r4190w 30초 warmup 기준선이다. 이전 main-control 시도는 `run_local.sh` 실행 권한 오류로 무효였고, 취소된 재시도도 사용하지 않았다.

측정 조건은 kairos 서버, source CPU 0–7, target CPU 8–15, warmup 30초, active 5초, 3회 중앙값이며 `measure.lock` 배타 잠금을 사용했다. L0·binding raw 결과와 main 기준선 raw는 표마다 연결했다. main 집계 근거는 [`r4190w/raw/aggregates/node.json`](../r4190w/raw/aggregates/node.json)이다.

reply 경로는 binding [`zlink-raw-server/main.js:79-86`]와 L0 [`l0-worker.js:49-60`]를 대조했다. 둘 다 수신 Message의 body를 protobuf decode하고, 매 요청에 protobuf로 새 Buffer를 encode해 새 `zlink.Message`로 복사한 뒤 raw response envelope와 body 두 파트를 submit한다. 요청 Message/part를 echo·forward·재사용하지 않는다.

## L0에서 끈 기능 위치

L0 분기는 [`main.js`](/root/worktree/zlink-v21-s033/lad-node/framework/bench/grpc/node/zlink-framework-server/main.js:36)에서 Framework route-mesh 시작 전에 선택된다. 실제 route-mesh 경로와 L0 직접 경로는 같은 bench handler class를 사용하지만, L0는 Framework dispatcher·DI 수명·operation registry를 실행하지 않는다. 표에서 “모방”은 Framework 동작 중 벤치에 필요한 부분을 직접 수행하는 코드를 뜻한다.

| 사다리 기능 | L0에서 끈 동작과 위치 | 사용한 경로 / 모방 여부 |
|---|---|---|

## L0에 남은 비용

request-serial 1K·4K의 미달 위치는 L0 수신·계측 경로다. `l0-worker.js:73-74`는 요청 큐가 빈 뒤 다음 request마다 `poller.wait()`로 깨어나고 `recv(DontWait)`로 처리한다. 직렬 요청은 inflight 1이라 이 대기가 매 왕복에 한 번 생긴다. raw binding server는 `zlink-raw-server/main.js:132-142`의 `setImmediate(pump)` 루프를 사용한다. 이 차이는 request-serial raw/client 쌍에서 소스 transport가 같고 L0 target만 달라지는 경계와 일치한다.

L0 계측은 활성 메시지마다 `l0-worker.js:18,21`에서 shared counter에 `Atomics.add`를 **2회** 수행한다. raw binding 계측 `shared/bench-server-metrics.js:33-40`은 같은 두 개수를 일반 JS `+= 1`로 올려 atomic RMW가 없다. 진단 CPU profile은 request-serial 1K를 실행해 raw 결과로 보존했다 (`raw/profile/request-serial-1k/`, profiler 파일은 `raw/profile/cpu/`). 이 profile은 client isolate만 기록되어 target worker의 CPU 비율을 말해주지 않는다. 남은 비용의 정량 근거는 위 atomic RMW 수와 1회-per-serial-request poller wait 코드 경로다. 이 실험의 L0 0.95 기준은 request-serial 두 셀에서 충족되지 않았다.

## 무효 자료와 검증

- main-control 시도 `raw/node-main-driver.log`는 실행 권한 오류, 재시도는 취소되어 사용하지 않았다. main 표에는 지정된 r4190w 기준선만 썼다.

- 바뀐 저장소 파일은 `framework/bench/grpc/node/client/main.js`, `run_local.sh`, `shared/raw-wire.js`, `zlink-framework-server/{bench-handlers.js,l0-worker.js,main.js}`다. 커밋은 `935c2db695` 및 `0950eeec22`; branch는 clean이며 push·PR은 하지 않았다.
