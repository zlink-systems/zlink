## 실행 증거와 판정 규칙

표 A의 유효 단계 값에는 중앙값 run의 `results.json`이 연결돼 있고 R/S 링크는 counted run의 결과와 scheduling 기록이다. 모든 유효 counted run은 errors=0, submitted=completed=received, 모든 source/target thread SCHED_OTHER, 시작·중간 affinity source 0–5 / target 8–13, C2/C3 disable=1을 통과했다. warm run은 `raw/java/<step>/<cell>/warm/`에 보존했으며 판정에 사용하지 않았다.

표 B는 손실을 `1 − new/previous`로 계산한다. L0 기준은 binding 대비 5% 이내, L1–L4는 단계당 7% 이내, L5~L7은 L4 대비 21% 이내다. 5–9% 손실 셀은 이전·신규 각 3회 측정했다. 3회 셀의 G5는 `max(|run−median|)/median`; G5 > 5%이면 판정 불가다. L5~L7의 19–23%는 3회 보강 구간이다.

초기 progress의 잘못된 서식 두 줄은 유효 수치나 판정으로 사용하지 않았다. C2/C3 준비가 안 된 L4 warm attempt 1은 bench phase 시작 전에 실패했고 판정에서 제외했다. L5~L7 request-backpressure 4K의 warm 및 counted 결과는 errors가 각각 [128,213](../lad-java-s2/raw/java/L5_7/request-backpressure-4096/warm/attempt1/run1/zlink-framework-java-request-backpressure-4096/results.json)·[123,625](../lad-java-s2/raw/java/L5_7/request-backpressure-4096/counted/attempt1/run1/zlink-framework-java-request-backpressure-4096/results.json)이고 submitted/completed/received가 달라 폐기했다.
