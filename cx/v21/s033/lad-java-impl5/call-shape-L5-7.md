# Java ladder L5_7 호출 형태

L5_7는 L4의 typed JSON `BenchTypedPayload`와 reply 의미를 유지하고, source와 target에서 정상 Framework route 경로를 사용한다. binding 열은 L4 직전 bench 경로다. 그 열과 L5_7 사이에서 L5~L7이 아닌 차이는 L1 permit, L2 envelope, L3 service-wire framing, L4 typed payload codec에 속한다.

## 확인한 결정 소유

- Owner queue와 handler worker 실행: `08-messaging-hot-path.ko.md` §4.1·§4.3·§4.4.
- Request operation 등록, deadline과 completion: `08-messaging-hot-path.ko.md` §3 E3~E5; terminal과 deadline 세부 소유자는 `01-submit-and-completion.ko.md` §10~§11.
- L6 current activation hotfix `62e4a644b2 (#4391)`는 Spot Actor handler 목록을 Spot 인스턴스가 소유하도록 한다. 이번 RouteMesh Channel handler 호출은 해당 Spot Actor 등록 경로를 쓰지 않으며, 현재 Spring handler activation/DI 동작을 사용한다.
- 표의 L5_7 행 외 차이는 복원 기능에 속한다. binding reply part 재사용, 추가 application counter, 별도 bench queue는 넣지 않았다.
