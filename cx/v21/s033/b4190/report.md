## 공통 계측·설정 접점

- C callback state의 completed/errors/outstanding/writable는 atomic이고 latency sampler는 callback에서 직접 쓰인다. 다중 submit자에 맞춰야 할 `request_metrics_t`의 submitted/blocked/max/wait는 평범한 필드다. ([bench_zlink_client.cpp](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/c/zlink/bench_zlink_client.cpp:26), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/c/zlink/bench_zlink_client.cpp:35))
- C++ 공통 `counters_t`의 수치값은 atomic이나 `error_summary`/`other_errors`는 비동기 callback 여러 개가 동시에 기록할 경우 보호되지 않는다. latency sampler는 driver run에서 공유 전달된다. ([bench_cpp_client.cpp](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/cpp/client/bench_cpp_client.cpp:78), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/cpp/client/bench_cpp_client.cpp:102), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/cpp/client/bench_cpp_client.cpp:226))
- .NET `SourceMetrics`는 모든 counters, samples, error map을 lock 하나로 보호한다. Java `Latencies`는 atomic cursor로 callback 스레드 샘플을 모으고 종료 때 정렬한다. Node는 단일 이벤트 루프에서 counters와 샘플 배열을 직접 누적한다. ([Program.cs](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/dotnet/Client/Program.cs:666), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/dotnet/Client/Program.cs:703), [Latencies.java](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/java/client/src/main/java/systems/zlink/bench/withgrpc/client/Latencies.java:8), [bench-core.js](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/node/client/bench-core.js:40))
- 공유 설정은 이미 `runner_common.sh`의 `SEND_CONCURRENCY=8`, `WINDOW=100`, HTTP trigger `sendConcurrency`다. Java/Node CLI 및 result metadata도 `sendConcurrency` 필드를 기록한다. C runner는 HTTP trigger가 아니라 환경변수만 전달하며, C++ runner도 동일 공통 trigger를 쓴다. ([runner_common.sh](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/runner_common.sh:8), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/runner_common.sh:190), [Java options](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/java/client/src/main/java/systems/zlink/bench/withgrpc/client/BenchOptions.java:38), [Java writer](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/java/client/src/main/java/systems/zlink/bench/withgrpc/client/BenchResultWriter.java:100), [Node main](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/node/client/main.js:27), [Node metadata](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/node/client/main.js:468), [C runner](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/c/run_local.sh:67))
- 현재 metadata에서 `request-backpressure`는 `count:1`, 무제한 in-flight로 기술되고 `send-saturation`만 `count:sendConcurrency`다. submitter 수를 별도 결과 필드로 남길 접점은 각 언어 result writer/metadata와 runner 공통 변수/trigger이며, Java 출력 예가 명시적이다. ([BenchResultWriter.java](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/java/client/src/main/java/systems/zlink/bench/withgrpc/client/BenchResultWriter.java:54), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/java/client/src/main/java/systems/zlink/bench/withgrpc/client/BenchResultWriter.java:86))

## 표면상 단일 submitter 전제와 위험

- C의 단일 `seq`, `request_metrics_t`, send의 `seq/blocked/errors/submit_wait_ms`는 동시 작성 시 병합 또는 동기화가 필요하다. callback atomic counters는 이미 공유 가능하지만 latency sampler 구현 확인이 필요하다. ([bench_zlink_client.cpp](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/c/zlink/bench_zlink_client.cpp:305), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/c/zlink/bench_zlink_client.cpp:417), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/c/zlink/bench_zlink_client.cpp:422))
- .NET/Java/C++ reply validators는 reply의 embedded sequence를 해당 제출과 대조하므로 FIFO 순서를 요구하진 않는다. 다만 sequence allocator를 공유하고, histogram/latency accumulator와 errors를 여러 writer에 안전하게 해야 한다. ([C++ bench_cpp_client.cpp](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/cpp/client/bench_cpp_client.cpp:747), [.NET BenchMeasurement.cs](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/dotnet/Client/BenchMeasurement.cs:590), [Java BenchDrivers.java](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/java/client/src/main/java/systems/zlink/bench/withgrpc/client/BenchDrivers.java:747))
- C++ Framework path는 `_seq++`가 shared driver state이며 request validation은 per-pending slot의 sequence로 검증한다. send completion counter도 공유된다. ([bench_cpp_client.cpp](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/cpp/client/bench_cpp_client.cpp:870), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/cpp/client/bench_cpp_client.cpp:948), [동일](/root/worktree/zlink-v21-s033/b4190/framework/bench/grpc/cpp/client/bench_cpp_client.cpp:737))
