Java Framework reply 제출 변경 보고서

1. ZLinkJavaRawServicePort.replyMessages는 인자 검증 후 router.reply(target, requestSequence).message(...).submit()을 직접 호출하고 모든 경로에서 Message.closeAll을 수행한다. reply의 인자 검증과 메시지 정리는 유지했으며, tcpNoDelay와 다른 socket 옵션 및 다른 state-lane 사용은 바꾸지 않았다. 변경은 framework/languages/java/zlink-framework-core/src/main/java/systems/zlink/framework/runtime/binding/ZLinkJavaRawServicePort.java:523-542에 있다. 제출 판정 위치는 변경 전 Framework port lane 및 owner 검사와 binding/Core의 두 곳이었고 변경 후 binding/Core 한 곳이다. ensureOwnedOnLane은 다른 포트 작업에서 계속 쓰여 제거할 dead helper가 없고 새 상태나 동기화 수단은 추가하지 않았다. 결정 소유자는 binding/Core이며, binding multipart 계약은 socket-local gate 없이 same-handle 동시 제출을 따른다고 정한다(bindings/doc/spec/README.ko.md:496-499); Java 계약은 reply가 source RID와 token을 capture하고 다른 owner token을 native 호출 전에 거부한다고 정한다(bindings/doc/spec/java/README.ko.md:959-963, 994-996). .NET 대응 경로도 별도 Framework lane 없이 Received.Reply().Messages(...).Submit()을 호출한다(framework/languages/dotnet/src/Zlink.Framework/Runtime/Service/ZLinkRawRouterServicePort.cs:237-254). 이 변경은 기존 Framework 중복 판정을 제거하는 B 분류다.

reply의 framework 내부 진입점은 ZLinkJavaRawServicePort.reply에서 replyMessages를 부르는 곳이다(framework/languages/java/zlink-framework-core/src/main/java/systems/zlink/framework/runtime/binding/ZLinkJavaRawServicePort.java:511-521). ZLinkJavaRawMeshNode의 reply 호출 지점은 같은 파일의 4217, 6195, 6338, 6355, 6378, 6431, 6689, 6867, 7401, 7421, 7443, 7496, 7506, 7526, 7558, 7645, 7672, 7999, 8042, 8053, 8137, 8401행이다. replyMessages 호출 지점은 6106, 6387, 6801, 7046, 7835행이다. 테스트의 직접 호출과 그 밖의 사용처는 ZLinkJavaRawServicePortContractTest 안에 있다.

2. 변경 전에는 이미 닫힌 port에서 reply를 시작하면 ensureOwnedOnLane이 먼저 IllegalStateException("service port is closed")를 던졌고, 소유되지 않은 router이면 IllegalArgumentException("router is not owned by this service port")를 던졌다(ZLinkJavaRawServicePort.java:709-713, 725-728). 변경 후에는 port의 별도 판정 없이 binding/Core에 제출한다. 닫힌 socket이면 Java binding의 IllegalStateException("socket is closed") 또는 Core 제출 오류가 발생한다(NativeSocketRuntime.java:299-301, CompletionOwner.java:247-251, 254-259, SocketCore.java:261-264). 다른 router의 ReplyToken이면 binding이 IllegalArgumentException("reply token belongs to a different router")를 낸다(NativeRouterSocket.java:90-100). 예외 문구의 소유자는 binding으로 바뀌지만 닫힘은 실패, 잘못된 소유권은 인자 거부라는 결과 종류를 유지한다.

예외를 처리하는 호출 경로 중 유지보수 응답 제출은 RuntimeException을 잡아 조용히 버린다(ZLinkJavaRawMeshNode.java:6431-6437). 세션 이전 확인 응답도 RuntimeException을 잡아 조용히 버린다(6689-6696). canonical actor join 응답은 RuntimeException을 잡아 실패 응답 제출을 시도한다(7645-7655). 원격 actor 응답의 whenComplete는 실패 시 메시지와 inbound를 닫고 작업 및 ordered relay를 완료한다(7881-7895). 이 경로들은 예외 하위 타입이나 문구를 분류하지 않는다. 따라서 이전의 silent drop, 실패 응답 시도, 실패 완료 결과와 관찰자 및 metric 경로는 그대로이고 새 metric이나 observer는 발생하지 않는다. 다른 호출부는 예외를 상위 완료·실패 경로로 전달하며 별도 타입 분류를 하지 않는다. replyMessages의 finally가 성공과 실패 모두에서 전달된 메시지를 닫는다(523-542).

런타임 닫기는 MeshNode를 중지하고 pump를 멈춘 뒤 operations를 닫고 receive-flow 등록을 해제한 다음 port.close를 호출한다(ZLinkJavaRawMeshNode.java:5362-5373, 5411-5425). port.close는 자체 operation을 닫고 receive poller와 ROUTER를 순서대로 닫은 뒤 소유 context를 닫는다(ZLinkJavaRawServicePort.java:651-675). 따라서 다른 스레드의 직접 reply는 ROUTER 닫기와 경합할 수 있다. 이미 닫힌 port 또는 runtime에 뒤늦게 제출한 reply는 binding/Core 오류로 끝나며 대기하지 않는다.

3. Java binding에서 RouterSocket.reply는 토큰 소유 router를 검사하고 제출 operation을 만든다(bindings/java/src/main/java/systems/zlink/runtime/sockets/NativeRouterSocket.java:90-100). NativeSocketRuntime.submitReply는 열린 socket을 확인한 뒤 CompletionOwner에 전달한다(NativeSocketRuntime.java:299-301). CompletionOwner.submitReply는 같은 handle 제출 경로를 사용하고 결과를 확인한다(CompletionOwner.java:247-251). 닫힘이 먼저 반영된 제출은 withNativeCall의 closed 검사에서 거부된다(CompletionOwner.java:254-259). native socket 닫기와 닫힘 상태 갱신은 CompletionOwner.closeNativeSocket에 있고(CompletionOwner.java:358-365), SocketCore는 이 닫기 경로를 사용한다(SocketCore.java:243-247). NativeSocketRuntime은 native handle을 닫은 뒤 Java handle을 비운다(NativeSocketRuntime.java:615-628). 이 binding/Core의 같은-handle 제출·닫기 조정으로 제출이 닫기보다 먼저 받아들여지거나 닫힘 오류로 거부되므로 in-flight reply와 socket close 경합이 안전하게 종료된다. 프레임워크 쪽 별도 lock이나 재검사는 필요하지 않다.

4. ZLinkJavaRawServicePortContractTest에 port/runtime close와 reply 제출 경합 테스트를 추가했다. 닫기와 겹친 제출은 성공 또는 binding/Core 실패로 끝나고, 닫기 후 제출은 socket closed 오류로 끝나며 Message가 소비되는지 확인한다. 여러 handler 스레드가 서로 다른 request token으로 동시에 답하고 각 요청자가 자기 응답을 받는 테스트도 추가했다. 변경된 검증 테스트는 nativeReplyPreservesWireBytesAndConsumesMessagesOnEveryTerminalPath, concurrentRepliesFromDifferentThreadsKeepTheirRequestTokens, replyRacingRuntimeCloseSucceedsOrUsesBindingCloseErrorAndConsumesMessage, replyRacingPortCloseSucceedsOrUsesBindingCloseErrorAndConsumesMessage이다.
