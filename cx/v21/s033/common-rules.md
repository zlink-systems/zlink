## Rules (all ladder jobs)
- Experiment branch only: commit locally, never push, never open a PR, never merge.
- PARITY (PM-agreed 11-12, extended 11-13 by kairos): the L-step bench server must do the binding (zlink-<lang> raw) server's work everywhere except the Framework features restored so far. RECEIVE: the same wait primitive and loop as the raw server (e.g. direct blocking recv, or the same setImmediate pump), the same drain, the same metrics counters (no extra atomics). REPLY: a new envelope part, a new protobuf body encode, the same part count and submit; never reuse the request parts. The only allowed difference at L0 is the direct call into one fixed handler. Before EVERY measurement write to progress.md the binding vs L-step receive excerpt and reply excerpt (file:line) side by side, plus the per-message waits/allocations/atomics/copies each does. Measure only when they match.
- FIRST OUTPUT (PM 11-13 11:46): before any measurement, write <job dir>/call-shape.md — a table comparing the binding bench and the L-step bench call by call, file:line on both sides, for all four paths: source send, target receive, target reply, source completion/receive of the reply. Columns: step, binding call (file:line), L-step call (file:line), same?, if different: which restored Framework feature it belongs to. Any difference not belonging to a restored feature = do not measure; fix the bench first and redo the table. G5 spread = largest |run − median| ÷ median; G5 applies to 3-run cells only; a 3-run cell failing G5 is "판정 불가", never a pass.
- Before EVERY measurement also write one progress.md line: built commit (`git rev-parse HEAD` + dirty flag), worktree base (`git merge-base HEAD origin/main`), binary/JAR paths under THIS worktree and their sha256. Never use /root/zlink builds. Chain build && verify the binary is newer than its sources && measure; never measure a stale build.
- Measurement only inside `flock /root/jobs/fx/cx/measure.lock` EXCLUSIVE via the job's tools/run-group.sh copy: kairos server, source CPU 0-7, target CPU 8-15 (during a hold the guard narrows them to 0-5 / 8-13 and moves everything else and IRQs to 6-7,14-15; PM 11-13 17:38), warmup Java/.NET 10 s, C++/Node 3 s, active 5 s (PM 11-13 15:29). Hold the lock only for the minutes of measuring: builds, call-shape, aggregation and analysis happen outside the lock. Every run: errors 0 and submitted = completed = received; discard broken cells. 
- C/C++ compiles only through /root/jobs/fx/cx/cpp-build-slot.sh (no outer flock; since 11-13 16:20 it takes no measure lock or gate — the guard pauses compiles during measurements), Release, USE_BINDINGS_SOURCE=ON, Core prefix /root/.cache/zlink/core-release/1.25.0/linux-x64, -j3, at most 25 GB; remove C++ build dirs at the end. Other languages build outside the measure lock, but while any measurement holds the lock the quiet guard pauses every build and test (all languages) and runs other agents SCHED_IDLE; expect pauses. Never run tests or benches outside these rules.
- Do NOT run scripts/dev/internal-docs.sh, git pull/fetch/push, GitHub, sub-agents or other AI tools. Keep every raw file; never delete raw outputs.
- Write progress.md as soon as the first number exists. When the time cap is reached, stop measuring immediately and write the report with what is complete.
- Korean, short tables; every number cites its raw file.
- MEASUREMENT METHOD (실장님 via PM 11-13 15:29, replaces the 12:08 session shape): default development measurement = previous step + new step only, the 6 cells, 1 run each, one lock hold (one language about 5-10 min). Step loss = new ÷ previous from THIS session; that decides improvement and the 7% rule. Only cells whose loss is on the 7% boundary (loss 5-9%) get 3 runs (previous + new, same hold if possible). A full 3-run confirmation of all cells happens once at L7 (or at the end of a step group), not per step. BINDING: measured once per language per day, 6 cells x 1 run, saved as /root/jobs/fx/cx/v21/s033/binding-daily/<lang>-<YYYY-MM-DD UTC>.json (cell -> msg/s + raw path); if today's file exists use it as the binding reference, otherwise measure binding first in the same hold and write the file. Ratio to binding uses that day's file.
- LOCK TIME LIMIT (PM 11-13 16:00): one measure.lock hold must not exceed 30 minutes. Plan holds to fit (quick method: about 5-10 min). A job whose hold passes 30 minutes is stopped on the spot by kairos; its finished cells are judged as they are, and missing cells move to the next quick session. Never queue a second hold to "finish" a long one.
- SCHEDULING CHECK (PM 11-13 16:32): at the start of every run and mid-active, record the scheduling policy of every thread of the source and target bench processes (chrt -p for /proc/<pid>/task/*) in the run's raw record. A run with any thread not SCHED_OTHER is invalid: discard it immediately and re-run. (Before 16:29:25 UTC the bench could inherit SCHED_IDLE from its agent.)
- PROVISIONAL WINDOW (PM 11-13 16:32): every result measured 12:05-16:29 UTC is 잠정, pass and fail cells alike (a slowed previous step makes the new step look better). After A/A (aa-noise3) is within G5 5%, re-measure those steps' 6 cells with the quick method. If A/A G5 exceeds 5%, stop ladder measurements and report the cause first.
- BINDING CONDITIONS (PM 11-13 17:10): since 17:07 UTC the guard disables C2/C3 during holds. Bindings measured before that (binding-daily/pre-cstate/) are not a reference any more. Every binding-daily file must state its conditions ("C2·C3 off, SCHED_OTHER") and be measured after 17:07 UTC; ratios divide only by a binding measured under the same conditions.
