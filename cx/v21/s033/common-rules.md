## Rules (all ladder jobs)
- Experiment branch only: commit locally, never push, never open a PR, never merge.
- PARITY (PM-agreed 11-12, extended 11-13 by kairos): the L-step bench server must do the binding (zlink-<lang> raw) server's work everywhere except the Framework features restored so far. RECEIVE: the same wait primitive and loop as the raw server (e.g. direct blocking recv, or the same setImmediate pump), the same drain, the same metrics counters (no extra atomics). REPLY: a new envelope part, a new protobuf body encode, the same part count and submit; never reuse the request parts. The only allowed difference at L0 is the direct call into one fixed handler. Before EVERY measurement write to progress.md the binding vs L-step receive excerpt and reply excerpt (file:line) side by side, plus the per-message waits/allocations/atomics/copies each does. Measure only when they match.
- FIRST OUTPUT (PM 11-13 11:46): before any measurement, write <job dir>/call-shape.md — a table comparing the binding bench and the L-step bench call by call, file:line on both sides, for all four paths: source send, target receive, target reply, source completion/receive of the reply. Columns: step, binding call (file:line), L-step call (file:line), same?, if different: which restored Framework feature it belongs to. Any difference not belonging to a restored feature = do not measure; fix the bench first and redo the table. G5 spread = largest |run − median| ÷ median; a cell still failing G5 after 5 runs is "판정 불가", never a pass.
- Before EVERY measurement also write one progress.md line: built commit (`git rev-parse HEAD` + dirty flag), worktree base (`git merge-base HEAD origin/main`), binary/JAR paths under THIS worktree and their sha256. Never use /root/zlink builds. Chain build && verify the binary is newer than its sources && measure; never measure a stale build.
- Measurement only inside `flock /root/jobs/fx/cx/measure.lock` EXCLUSIVE via the job's tools/run-group.sh copy: kairos server, source CPU 0-7, target CPU 8-15, warmup 30 s, active 5 s. L-step and binding in the same session. Every run: errors 0 and submitted = completed = received; discard broken cells. A cell whose runs fail the aggregator G5 spread check gets 5 runs.
- C/C++ compiles only through /root/jobs/fx/cx/cpp-build-slot.sh (no outer flock), Release, USE_BINDINGS_SOURCE=ON, Core prefix /root/.cache/zlink/core-release/1.25.0/linux-x64, -j3, at most 25 GB; remove C++ build dirs at the end. Other languages build outside the measure lock, but while any measurement holds the lock the quiet guard pauses every build and test (all languages) and runs other agents SCHED_IDLE; expect pauses. Never run tests or benches outside these rules.
- Do NOT run scripts/dev/internal-docs.sh, git pull/fetch/push, GitHub, sub-agents or other AI tools. Keep every raw file; never delete raw outputs.
- Write progress.md as soon as the first number exists. When the time cap is reached, stop measuring immediately and write the report with what is complete.
- Korean, short tables; every number cites its raw file.
- SESSION SHAPE (PM 11-13 12:08): every measurement session measures binding, the previous step and the new step together, same cells and run counts, so the previous step is re-confirmed in the same conditions. Step loss uses the previous step's ratio from THIS session.
