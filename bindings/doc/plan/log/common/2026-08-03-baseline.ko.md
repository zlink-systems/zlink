# Python·Go·Rust Core 0.9.0 최신화 기준선 — 2026-08-03

> 대상 독자는 최신화 작업을 시작하기 전에 공통 계획의 현재 수치와 파일 경로를 재검증하는 구현 담당자다.
> 이 log는 “계획을 작성할 때 어떤 revision과 runtime을 확인했으며, 왜 새 candidate package가 필요한가?”에
> 답한다.

## 조사 범위

조사한 repository revision은 `ad1f63ae54690d354e4298ce655b52220b4d0b5b`다. `VERSION`, `core/include`,
`core/build/lib`와 세 bindings의 source·native payload에는 조사 전에 추적되지 않은 변경이 없었다. 계획 문서
변경은 이 범위에 포함하지 않았다.

## Core build 상태

`VERSION`과 `zlink_version()`은 모두 `11.1.0`이었다. 그러나 공개 socket header가 runtime보다 나중에
수정되어 현재 `core/build`은 package 입력으로 사용할 수 없다.

| 파일 | 수정 시각(Asia/Seoul) | SHA-256 또는 판정 |
|------|-----------------------|------------------|
| `core/include/zlink/socket/api.h` | 2026-08-02 16:38:17 | runtime보다 나중에 수정됨 |
| `core/build/lib/libzlink.so.0.1.0` | 2026-08-02 16:10:33 | `fc12e01c334f60d5fe1716e67e6c036e299988144a70d49a15288e6de77dca8d` |

확인 명령은 다음과 같다.

```bash
git rev-parse HEAD
git status --porcelain=v1 -- VERSION core/include core/build/lib \
  bindings/python bindings/go bindings/rust
stat -c '%n|size=%s|mtime=%y' \
  core/include/zlink/socket/api.h core/build/lib/libzlink.so.0.1.0
sha256sum core/build/lib/libzlink.so.0.1.0
```

`git rev-parse HEAD`는 위 revision을 출력했고 종료 코드는 0이었다. 이어 실행한 `git status`는 아무것도
출력하지 않았으며 종료 코드는 0이었다.

Version은 다음 명령으로 확인했다. Python에서 `ctypes.CDLL`에 runtime의 절대 경로를 넘겼다. 이어
`zlink_version()`이 채운 major, minor, patch 값을 읽었다.

```bash
python3 - <<'PY'
import ctypes
from pathlib import Path

for path in (
    Path("core/build/lib/libzlink.so.0.1.0"),
    Path("bindings/python/src/zlink/native/linux-x86_64/libzlink.so.10.6.0"),
):
    runtime = ctypes.CDLL(str(path.resolve()))  # 검사할 파일을 절대 경로로 load한다.
    major, minor, patch = ctypes.c_int(), ctypes.c_int(), ctypes.c_int()
    runtime.zlink_version(
        ctypes.byref(major), ctypes.byref(minor), ctypes.byref(patch)
    )
    print(f"{path}|{major.value}.{minor.value}.{patch.value}")
PY
```

종료 코드는 0이었고 핵심 출력은 다음과 같았다.

```text
core/build/lib/libzlink.so.0.1.0|11.1.0
bindings/python/src/zlink/native/linux-x86_64/libzlink.so.10.6.0|10.6.0
```

이 결과는 runtime 내부 version만 증명하며 header보다 오래된 상태를 해소하지 않는다.

## Linux payload 기준선

세 bindings의 Linux payload는 같은 파일 hash를 사용한다. x86_64 runtime은 `10.6.0`을 반환하고 SONAME은
`libzlink.so.10`이다. aarch64 runtime은 파일명과 SONAME이 `libzlink.so.9`이므로 Core 0.9.0 package가 아니다.

| Binding | x86_64 payload SHA-256 | aarch64 payload SHA-256 |
|---------|------------------------|-------------------------|
| Python | `5f69136e5d7c975803c977b312736be9f86901be506b06df38900288c0975919` | `9c3cf64ca56e15b9f2200e33d377d5ce8f19d4fcc180a941f6a5c51442170391` |
| Go | `5f69136e5d7c975803c977b312736be9f86901be506b06df38900288c0975919` | `9c3cf64ca56e15b9f2200e33d377d5ce8f19d4fcc180a941f6a5c51442170391` |
| Rust | `5f69136e5d7c975803c977b312736be9f86901be506b06df38900288c0975919` | `9c3cf64ca56e15b9f2200e33d377d5ce8f19d4fcc180a941f6a5c51442170391` |

Payload root는 각각 `bindings/python/src/zlink/native/`, `bindings/go/native/`, `bindings/rust/native/`다.
`sha256sum`과 `readelf -d`로 hash와 SONAME을 확인했다. x86_64 version은 같은 `ctypes.CDLL` 검사로 확인했다.
aarch64 runtime은 현재 x86_64 host에서 실행하지 않았으므로 파일명·ELF SONAME 증거와 실제 native consumer
증거를 구분한다.

## Service 계약 기준선

Core의 root header에는 service include가 없다. Go와 Rust의 복사된 `include/zlink.h`는
`zlink/service/common.h`, `dispatch.h`, `mesh_node.h`, `spot.h`, `actor.h`, `stream_session.h`를 include한다.
Python의 `src/zlink/contracts/service/`와 `src/zlink/_runtime/service/`도 존재한다.

다음 명령으로 root header와 service source를 다시 확인할 수 있다.

```bash
rg -n '^#include.*service|zlink/service' \
  core/include/zlink.h bindings/go/include/zlink.h bindings/rust/include/zlink.h
find bindings/python/src/zlink/contracts/service \
  bindings/python/src/zlink/_runtime/service \
  bindings/go/include/zlink/service bindings/rust/include/zlink/service -type f
```

이 log는 착수 기준선이다. 승인된 candidate, package와 clean consumer의 완료 증거로 재사용하지 않는다.
